# Протокол экспериментов

## Что сравниваем

Внутри каждого эксперимента используется одна модель и одна ревизия исходных
весов. INT8 и INT4 получены из локальной FP16-копии, размер группы — 64.
Неквантованные параметры остаются FP16. Версии библиотек и настройки сохранены
рядом с исходными измерениями. Qwen и SmolLM2 образуют отдельные эксперименты.

## Скорость и память

```sh
.venv/bin/python scripts/benchmark_mlx.py --model qwen2.5-0.5b
```

Один запрос за раз, 128 токенов на входе и 128 на выходе. Вход — повторяемый
текст, обрезанный до нужной длины; это нагрузка для скорости, не тест знаний.
Перед 10 измерениями выполняются 3 полных прогрева. Каждый формат запускается
в отдельном процессе; порядок перемешан с seed=42 и сохранён в manifest.json.

В каждом повторе создаётся новый неквантованный KV-cache. EOS не завершает
генерацию раньше времени. Цикл выбирает argmax и синхронизирует GPU после
каждого токена. Загрузка модели, токенизация и перенос результата в Python
исключены из времени генерации.

- TTFT: время prefill и выбора первого токена.
- Decode tokens/s: (число выходных токенов − 1) / время после первого токена.
- Память: пик выделений аллокатора MLX во время генерации, включая веса.
  Счётчик сбрасывается перед повтором. Это не RSS процесса и не пик загрузки.
- Размер весов: байты файлов safetensors, включая метаданные и масштабы.
  Полный размер каталога модели записывается отдельным полем.

Отчёт содержит медианы, минимум/максимум и межквартильный диапазон Q1–Q3.
IQR описывает разброс, но не является доверительным интервалом. Прогретый
аллокатор сохраняется между повторами; содержимое KV-cache — нет.

Для каждого запуска сохраняются исходные наблюдения, токены, ревизия модели,
версии библиотек, состояние питания и хеш скрипта. Незавершённые результаты
и ошибки тоже сохраняются. Изменение комментариев меняет хеш файла, но не
пересчитывает и не подменяет уже полученные результаты.

## Perplexity

```sh
.venv/bin/python scripts/evaluate_ppl.py --model qwen2.5-0.5b
```

Корпус: WikiText-2 raw, test, ревизия
`b08601e04326c79dfdd32d625aee71d232d685c3`.
Строки соединены двумя переводами строки, пустые строки сохранены. Берём
первые 16 384 токена; специальные токены не добавляем. Для каждого формата
одной модели входные токены одинаковы. Первый токен служит контекстом;
оценены 16 383 следующих токена.

Окно 512, шаг 256, batch=1, без KV-cache. Цели в перекрывающемся контексте
не учитываются повторно. Logits переводятся в FP32 перед logsumexp и
вычитанием logit правильного токена. Сначала суммируем NLL, затем делим
на число целей и берём exp. Усреднять perplexity отдельных окон нельзя.

Сохраняются NLL каждого окна, число целей, токены корпуса, хеш исходного файла
и ревизии. `--max-tokens 0` включает весь test. Опубликованный результат
относится к фиксированному фрагменту, не к полному корпусу.

Для тех же позиций считаем next-token top-1 accuracy: предсказание правильное,
если argmax по словарю совпал с фактическим следующим токеном. Для accuracy
сохраняем 95% Wilson interval. Сохранение качества определено как
`accuracy_quantized / accuracy_fp16`; его 95% интервал считаем парным bootstrap
по совместным результатам на одних и тех же токенах, 10 000 выборок, seed=42.

## Формулы сравнения

```text
экономия памяти = 1 − peak_quantized / peak_fp16
ускорение decode = tokens_per_second_quantized / tokens_per_second_fp16
изменение PPL = ppl_quantized / ppl_fp16 − 1
сохранение качества = next_token_accuracy_quantized / next_token_accuracy_fp16
```

Отношение PPL — не доля сохранённого качества. Next-token accuracy — узкая
языковая метрика, а не доля всех способностей LLM. Accuracy на прикладных
задачах пока не измерена. Настройку групп и слоёв следует проводить на validation
или calibration, не подбирать её по уже просмотренному test.

## Границы выводов

Одна машина, один размер нагрузки, один процесс на формат. Состояние питания
не отражает всю историю нагрева и фоновых процессов. Скорость относится к
синхронному циклу проекта, а не к максимально оптимизированному serving.

Проверочные smoke-запуски используют другой путь исполнения — их скорость
не смешивается с benchmark. Между моделями разная токенизация, поэтому
абсолютная PPL напрямую не сравнивается. Пересечение WikiText с данными
предобучения моделей не исключено.

Источники: [WikiText](https://huggingface.co/datasets/Salesforce/wikitext),
[определение PPL и оконная оценка](https://huggingface.co/docs/transformers/perplexity).
