# LLM Quantization & Efficient Inference

Сравнение FP16, INT8 и INT4 на **Qwen2.5-0.5B** и **SmolLM2-135M**.
Проект запускается на Apple Silicon через MLX: конвертирует веса, генерирует
текст и измеряет, что квантование меняет в скорости, памяти и perplexity

Основной эксперимент с Qwen2.5-0.5B на Apple M2 с 16 ГБ памяти.
INT4 ускорил декодирование в **1,65 раза** и снизил пиковую выделенную память
MLX на **62,1%**, но увеличил perplexity на **18%**. INT8 дал более мягкий
компромисс: **1,43×** по скорости при росте perplexity на **0,09%**

## Запуск

Проверенное окружение: macOS 14.6, Apple M2, Python 3.13.2, MLX 0.32.2,
MLX-LM 0.31.3. Для GPU нужен обычный терминал с доступом к Metal

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-mlx.lock.txt
python scripts/run_smoke_matrix.py --model qwen2.5-0.5b
```

Последняя команда скачает исходную модель и подготовит три локальных варианта.
Весам, кэшу и окружению нужно несколько ГБ диска; в Git они не хранятся.

```sh
# Скорость и память
python scripts/benchmark_mlx.py --model qwen2.5-0.5b

# Предсказание следующего токена на WikiText-2
python scripts/evaluate_ppl.py --model qwen2.5-0.5b

# Потоковое продолжение текста
python scripts/infer.py --model qwen2.5-0.5b --format int4 --prompt "Квантование нейросетей позволяет" --max-tokens 128
```

Используется **base**, не Instruct-модель: CLI продолжает текст без шаблона чата.
Доступны `--temperature` и `--seed`. Для SmolLM2 замените значение `--model`
на `smollm2-135m`. Без этого аргумента сохранён прежний выбор SmolLM2.

## Что внутри

- `src/llm_quantization/reference.py` — учебный симметричный квантователь,
  восстановление весов и упаковка двух INT4-кодов в байт.
- `scripts/quantize_mlx.py`: настоящее групповое affine-квантование через MLX
- `scripts/benchmark_mlx.py`: повторные измерения с отдельными процессами
- `scripts/evaluate_ppl.py`: NLL и perplexity с перекрывающимися окнами
- `scripts/infer.py`:  локальная генерация текста
- `tests/`: численные границы, упаковка, учёт токенов и выбор модели
- `results/` : исходные измерения, настройки и отчёты обоих экспериментов

Собственный квантователь нужен для разбора математики. Он хранит Python-объекты
и не ускоряет инференс. Оптимизированные операции для реальных моделей даёт MLX
В affine-формате учитываются масштабы и смещения, а часть параметров остаётся
в FP16. Поэтому фактический размер больше идеальных 4 или 8 бит на вес

```sh
PYTHONPATH=src python -m unittest discover -s tests -v
```

## Как читать результаты

Размер файлов весов, пиковая память MLX и RAM всего процесса — разные величины
Мы измеряем первые две. Скорость из короткого проверочного запуска нельзя
смешивать с benchmark: там другой цикл генерации и нет прогрева

Абсолютные PPL Qwen и SmolLM2 напрямую не сравниваются: у них разные токенизаторы
Настройки настраиваются на validation/calibration, не на уже просмотренном test
Accuracy на прикладных задачах пока не измерена; утверждения о «97% качества» нет
